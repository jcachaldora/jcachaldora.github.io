Document processing for an independent law firm

Problem
Court documents arrive as PDFs by email. Reading, data extraction and classification are manual, one document at a time.
Design
A mail inbox feeds a no code orchestrator. The orchestrator extracts the text from the PDF, sends it to a language model through an API to structure the content, checks that structured output against the fields the firm expects, writes the result to a spreadsheet, files the document in cloud storage and notifies the person responsible through a messaging app.
Architecture
Eight modules in sequence, plus a dedicated error handler.
Status
Built and running.

  2. 02Attachment capture
  3. 03PDF text extraction
  4. 04Language model extraction
  5. 05Output validation
  6. 06Spreadsheet write
  7. 07Cloud storage filing
  8. 08Messaging notification

Commercial triage for an insurance brokerage

Problem
Repeat sales questions take time away from selling.
Design
The most frequent questions are sorted into a small set. Each one gets a prerecorded voice reply sent through messaging. Anything outside that set goes to a person.
Method
Survey the repetitive tasks that actually happen before automating anything, then compare the model's answers against the answers the team writes by hand.
Status
Discovery and evaluation.
